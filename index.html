Identity Acceptance Surfaces

You can measure a password. Can you measure a face?

Where an identity stops being accepted — measured on the hardware actually deployed.

Move a face away from an enrolled identity in controlled steps of measured size — inside a generator whose space we control, rather than by nudging an embedding an operator has no access to — and map where the real discriminator flips from accepting to rejecting it. Along chosen geometric directions, not random noise. Built for INT8 / edge deployments, where a single threshold and a population rate hide how far the accepted region actually reaches, and how differently it reaches in different directions and for different people.

Underneath it is an operator’s question. A service that buys a face-verification system from a vendor is handed population rates — and may benefit from, want, or be obliged to know what those rates hide: how the system treats each person actually enrolled, on the device actually installed. This is a process for finding that out, against a black box, with perturbations of measured size. The argument · what it means for the data.

Each shell is an initial sample at known distances from the anchor identity, in the embedding metric — that first pass is run against the system under test. Per direction, those results show where a new test case is needed to pin down the acceptance threshold; across many directions that builds up the acceptance surface, which we compare to the ideal one.
