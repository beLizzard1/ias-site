Where we are

Project status

Last updated 2026-08-22

A running snapshot of what's built, the findings that are steering the work, and what's in flight. Honest about the rough edges.

Perturbation core

Done

Embeddings-first shells with exact cosine geometry — unit(anchor + ε·tangent), cos = 1/√(1+ε²) — and reproducible, index-addressable sampling. Test suite green; the documented quickstart runs end to end.

Real anchor extraction

Done

Real 512-D anchors extract from photos via InsightFace / antelopev2, and a shell dataset builds and probes around a real identity locally (no GPU needed for the embedding dataset itself). Fixed a recognition-model-selection bug and pinned the model pack with a verified digest.

Face compositor

Done

Warps and blends a generated face into a real background photo, keeping the real hair and scene. A face-interior mask removes the doubled-hairline seam; a hair-aware pass re-lays strands that fall over the face.

Finding: the compositor itself is near-lossless — putting a face back into its own photo differs by at most one level per pixel.

Rendering (Arc2Face)

Works, with a caveat

Face generation from an embedding runs end to end. The limitation is fidelity: the model reconstructs facial structure from the identity vector but fills in hair, colour, and presentation from its own prior, so renders can look stylised and not match the person.

For the measurement this matters little — the edge model crops around facial landmarks, so background and hair realism are for human-facing figures, not for what the device sees.

Edge model (ESP-DL)

Fixed & verified; chip parity open

The “identical embeddings” bug is resolved. Differential testing against an independent int8 reference — tracing every node, each tensor in its own buffer — localised three defects, all in the vendor's generic C/C++ fallback path that only a host build exercises: a packed Conv filter layout the loader didn't unpack, a PReLU kernel skipping requantisation, and a memory planner aliasing every tensor to the same offset. Two are reported upstream (#319, #320); the #319 fix is submitted as PR #321, and the memory-planner defect was already fixed on esp-dl's own master.

The submodule has since been bumped to esp-dl v3.3.9 — which needed one more host-only fix, for pixel-conversion Kconfig symbols left undefined off-device — and results are unchanged: black/noise frames return no face, same-identity pairs score roughly 0.6–0.78 cosine, cross-identity pairs roughly ±0.16. That's agreement with an independent reference, not with the chip — the open question the on-device harness exists to close.

Refined acceptance surface

First surface measured

Per-direction boundary search on 20 rays around one real identity (Dr James’), bisected against the ESP-DL SiL to ±0.03 ε, three renders per test point (median score, majority verdict). 18 of 20 rays bounded inside the dataset; 2 right-censored at the dataset's cos 0.60 edge.

Boundary angle mean 32.7° ± 12.9°, range 6.8°–49.5°. The most tolerant bounded direction reaches 7.2× further from the anchor than the least tolerant — an isotropic discriminator would draw a flat circle; this INT8 model draws a star. See the Explorer for the plotted surface and the caveats (pilot scale, one identity, renderer noise inside the measurement, detector threshold relaxed to 0.3, host-vs-silicon parity still open).

Higher-resolution refine pass

In progress

Refining 44 more directions (rays 20–63) against the same anchor and SiL, to fill out the surface beyond the first 20 rays. Running now — no results yet.

On-device harness

Started

The ESP32-S3 board is now visible to the toolchain inside the dev container. The esp-dl human_face_recognition firmware was built and flashed today, and the device produced its first inference: similarity 0.797307 on the example's own faces, versus 0.787880 for the same pair on the host runner. That's a first parity datapoint, not yet a parity study — settling host-vs-device agreement across a real spread of inputs is the next step before the device can serve as the faithful SUT for surface mapping.

The through-line

  • The perturbation stays in identity space at known amplitudes — that's what makes a boundary crossing meaningful.
  • Realism is for communicating with humans; the device crops to the face, so the surface it maps is unaffected by the surrounding scene.
  • Rendering is done lazily on a chosen subset — never all points up front — and those renders double as the inputs that seed the search on the real device.
